PacketStory reads a **pcap or pcapng** capture and writes what happened in plain sentences: *the workstation asked the resolver for example.test, connected to it over TLS, sent 376 bytes and received 5 KiB, and closed normally.* Every line cites the **packet numbers** it rests on, so you can check it in a packet viewer. A short **Worth a look** list points at a few patterns, labelled as heuristics.

**Pre-release.** An engineering tool for demonstration and controlled trials, not for unattended production use.

### What it does

- Readers for classic pcap (both byte orders, microsecond and nanosecond) and pcapng (section, interface and packet blocks, timestamp resolution); damaged tails end the read with a warning.
- Decoding of Ethernet (with VLAN tags), Linux cooked, raw IP and loopback links; IPv4, IPv6 (extension headers, fragments flagged), ARP, TCP, UDP, ICMP and ICMPv6.
- Light readers for DNS (with compression-pointer and length bounds), plain HTTP/1.x requests and responses, and the TLS ClientHello server name. Credentials are never kept.
- Conversations with TCP state (handshake, refused, unanswered, reset, mid-connection capture) and names learned from DNS answers in the same capture.
- A timeline in plain words where every line cites its packets, plus "worth a look" notes for possible port scans, repeated failed DNS lookups and credentials sent over cleartext HTTP.
- `packetstory summary`, `flows` and `story` (`--format md|html|json`, `--out`, `--max-events`, `--strict`). Exit codes: 0 ok, 1 error, 2 damaged capture with `--strict`.

### Known limitations

- **Heuristics, not verdicts.** The *Worth a look* rules are simple and can be wrong either way. A quiet report is not proof that nothing happened.
- **Tested on synthetic captures.** The lab and the fuzzing are hand-built. Real captures from other tools, odd link types and unusual traffic may expose gaps. Send a sanitised reproduction if one fails.
- **No reassembly, no checksums.** IP fragments are flagged, not reassembled; TCP streams are not reordered; checksums are not validated. Anything split across packets (a TLS hello in two segments, say) may be missed.
- **Plain HTTP and TLS server names only.** HTTP/2, QUIC, SMB, TLS contents and every other protocol appear only as conversations with byte counts.
- **A capture claims, it does not prove.** Spoofed or injected packets are described as they appear.
- **Whole file in memory.** Files up to 256 MiB and 5 million packets are accepted. The recorded scale run peaked at about 226 MiB for 52 MiB of capture.
- **Not yet verified on Windows by hand.** CI runs the tests on Windows; nothing has been checked against a real Windows workflow.

Checksums are in `SHA256SUMS`. See the [changelog](https://github.com/5K-bit/PacketStory/blob/v0.1.0/CHANGELOG.md) for details.
